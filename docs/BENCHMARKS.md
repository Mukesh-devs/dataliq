# Benchmarks

Performance budgets come from `BUILD_PLAN.md`. Numbers are recorded per OS
and per version.

**Machines**

- `linux-dev`: Linux container, 4 vCPU, 15 GB RAM, SSD, Ubuntu 24.04.
  (Fewer cores than the 8-core reference laptop in the plan; numbers are
  conservative.)

## Micro benchmarks (criterion)

Run with `cargo bench --profile dev` (dependencies at `opt-level = 2`) or
`cargo bench` (full release profile).

| Benchmark | What it measures | linux-dev (dev profile) |
| --- | --- | --- |
| `arrow_ipc_1000_rows_table` | one grid page: `SELECT *` of 1,000 rows × 6 mixed columns from a table, encoded as Arrow IPC | 0.58 ms |
| `arrow_ipc_1000_rows_generated` | same, rows generated by the query itself | 1.02 ms |

| `paging::pages_50m_rows_fast` (on demand) | random 500-row page from a 50M-row table by rowid range | 6.3 ms |

_Recorded during v0.1 steps 3 and 6._

## Performance budgets

Measured on `linux-dev`. Full tables per OS are recorded at each version tag.

| Flow | Budget | Measured | When |
| --- | --- | --- | --- |
| First rows of a 100 MB CSV (inspect + 1,000-row preview) | — | 0.36 s | v0.1 step 5 |
| First rows of a 5 GB CSV | < 1 s | 0.30 s | v0.1 step 5 |
| First rows of a 5 GB .csv.gz (109M rows, ~12.5 GB uncompressed) | < 2 s | 1.23 s (test), 1.04 s in the app | v0.1 step 5 |

| Full import of a 100 MB CSV (908K rows) | — | 2.2 s | v0.1 step 7 |
| Full import of a 100 MB .csv.gz (2.1M rows) | — | 3.8 s | v0.1 step 7 |
| Full import of a 5 GB CSV (45.8M rows) | report (aim < 60 s) | 31.9 s (168 MB/s), cache file 0.96 GB | v0.1 step 7 |
| Full import of a 5 GB .csv.gz (109M rows) | report | 98.5 s (55 MB/s compressed, ~127 MB/s uncompressed), cache file 2.27 GB | v0.1 step 7 |
| First rows of a 5 GB .ndjson.gz (106M rows) | < 2 s | 0.35 s | v0.1 step 8 |
| Full import of a 5 GB .ndjson.gz | report | 94.6 s, cache file 1.83 GB, peak RSS 3.0 GB | v0.1 step 8 |
| Open a 50M-row Parquet (inspect + row count + preview) | < 1 s | 0.046 s | v0.1 step 8 |
| Random 500-row page of a 50M-row Parquet (in place) | < 100 ms | 22.9 ms | v0.1 step 8 |
| Reopen a cached file | < 1 s | 1–2 ms | v0.1 step 7 |
| Peak memory while importing 5 GB | < DuckDB limit + 300 MB (8,045 + 300 MiB) | 1.9 GB (CSV), 3.2 GB (.csv.gz) | v0.1 step 7 |

Import numbers come from `cargo test -p bigview --test perf_import -- --ignored --nocapture
--test-threads=1`; peak memory is the process's `VmHWM`. Gzip decompression is single-threaded,
so `.csv.gz` imports are bounded by it (plus our parallel integrity check on another core).

Preview numbers come from `cargo test -p bigview --test perf_preview -- --ignored --nocapture`
(dev profile) and the app's status bar.
